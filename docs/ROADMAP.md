## 0. Зафиксированные решения (гриль-сессия 2026-07-20)

Решения приняты на обсуждении плана; при конфликте с более старым текстом побеждают они
(спека обновлена синхронно).

| # | Вопрос | Решение |

Технические допущения (принимаются без отдельного обсуждения, фиксируются здесь):

- **Сериализация:** System.Text.Json (NuGet, netstandard2.0-совместим) для чтения/записи
  JSON; **собственный канонический писатель** (упорядоченные ключи, invariant culture,
  фиксированный формат чисел) — для `InputHash` и байт-воспроизводимого паспорта.
- **Хэш:** SHA-256 поверх канонической сериализации.
- **Тесты:** xUnit (есть) + **CsCheck** для property-инвариантов; snapshot-тесты — 
  закоммиченный канонический JSON + строковое сравнение (без Verify и прочих зависимостей).

## 1. Цели Phase 1 (явные, проверяемые)

- **G1.** Core v2 решает T1 (реальный контур + проёмы) на golden-зданиях с порогами
  приёмки §12 спеки: 0 sliver'ов, 0 нарушений норм-параметров, BOM ≥99%, сохранение площади.
- **G2.** D1 работает насквозь: сдвиг окна в Revit → пересчёт меняет только затронутые
  ключи, теги/размеры нетронутых элементов живы (демо на реальном документе).
- **G3.** D6 работает: каждый элемент несёт `Provenance`; паспорт расчёта
  воспроизводится байт-в-байт.
- **G4.** Адаптер v2: извлечение FR-1…FR-4 + diff-материализация §9.2; v1-типы и старые
  команды удалены; плагин демонстрируется на здании с проёмами end-to-end.
- **G5.** Схема `SystemDefinition` бумажно доказана против кассеты (модуль под заказ),
  планкена (только курсы) и скрытого кляммера (смена крепления) — без правки схемы.
- **G6.** Трек E закрыт: отчёт по Renga-спайку и отчёт по Кадет-Вентфасад существуют;
  честностные клаузы («CAD-независимость — гипотеза до E2») имеют владельца и статус.

## 2. Правила выполнения

- **Облако:** только `RevitNvf.Core` + `RevitNvf.Core.Tests` (в контейнере нет Revit;
  SessionStart-хук определяет отсутствие SDK). Вся веха A–C — облачная.
- **Windows-сессии:** пакетами — авторство `.rvt`-фикстур, адаптер (веха D), smoke.
- **Ворота Р3:** до прохождения C4 адаптер и v1-типы не трогаются вообще.
- **Определение «сделано»:** код + тесты + обновлённые docs; запись каталога F1–F10 без
  `.rvt`-фикстуры считается нереализованной (клауза честности №8).
- Детерминизм-ворота CI (§11 спеки) включаются с первого шага, не в конце.

## 3. Шаги

### Веха A — геометрический фундамент (облако, ~4 нед)

**A1. Каркас v2 и примитивы.**
Пакеты: Clipper2 → Core, CsCheck → Tests. Типы: `Tol` (единая политика допусков),
`Vector2d`, `Point3d`, `Vector3d`, `Ring` (валидация: замкнутость, отсутствие
самопересечений, снап к сетке 0,1 µm, ориентация CCW-внешний/CW-дыра). Канонический
JSON-писатель + SHA-256 `InputHash`.
*Приёмка:* тесты валидации `Ring` (включая вырожденные входы); канонизация:
одинаковые данные → байт-идентичный JSON на любой культуре ОС.

**A2. `PlanarRegion` и булева обёртка.**
`PlanarRegion` (внешний Ring + дыры + `FaceFrame`); обёртка над Clipper2: union,
subtract, пересечение ячейки с регионом. Корпус болевых кейсов: дыра касается контура,
коллинеарные рёбра, микро-щели < Tol, дыра в дыре (отказ), совпадающие вершины.
*Приёмка:* property-тесты (CsCheck): сохранение площади при subtract; результат не
зависит от порядка дыр; повторный прогон байт-идентичен. Корпус кейсов зелёный.

**A3. Оболочка, вход конвейера, golden-каркас.**
`FaceFrame` (мировая привязка, V = гравитационная вертикаль), `BuildingEnvelope`
(в Phase 1 — одна грань; контракты `CornerEdge`/`LevelBand` существуют и сериализуются),
`GeometryInput` DTO + JSON-схема фикстур; snapshot-каркас golden-тестов; CI-ворота:
два прогона байт-идентичны, перестановка граней → идентичный результат.
*Приёмка:* первая golden-фикстура (стена с одним окном) проходит каркас насквозь
(пока без раскладки — только извлечённый регион).

### Веха B — система как данные (облако, ~3 нед)

**B1. `SystemDefinition` + `SubstructureSpec` + генерик-система.**
Схема по §4.2 спеки: авторитеты модуля/шва, политика реза, ограничения
`{min, max, default, normRef}`; `SubstructureSpec` с полной схемой `WindZone[]`
(в Phase 1 вычисляется только `OpeningMargin`). Версионируемый JSON. Первый документ:
генерик «керамогранит 600×600, видимый кляммер, вертикальные направляющие» — все числа
с `normRef` (Р4). Модель нарушений: `RuleId`, `NormRef`, факт/допуск, предложение.
*Приёмка:* документ системы валидируется схемой; round-trip сериализации байт-точен;
таблица параметров генерика сверена с СП 426 / ГОСТ Р 58154-55 (ссылки в normRef).

**B2. Бумажная валидация схемы (G5).**
Три кислотных теста как design-doc + компилируемые заглушки стратегий: металлокассета
(модуль под заказ), планкен (только курсы, без вертикальной сетки), скрытый кляммер
(смена `IAttachmentStrategy`, другие краевые отступы). Найденные дыры схемы чинятся здесь.
*Приёмка:* каждый тест показывает, что система выражается **данными + выбором стратегии**,
без правки схемы; документ с выводами в `docs/`.

### Веха C — конвейер (облако, ~10 нед)

**C1. Стадия 3: SubstructureLayout (FR-5…FR-7).**
Кронштейны по маске региона: зоны исключения у проёмов (`OpeningMargin`), краевые
минимумы, уплотнение по откосам/перемычкам; привязка кронштейнов к колоннам направляющих.
Направляющие: разрезка на сегменты над/под проёмами, поля сплайса и фикс/скольжения
(солвер — Phase 3, поля — сейчас).
*Приёмка:* property-инварианты: ни одного кронштейна в зоне исключения; каждый кронштейн
на направляющей; golden-снапшоты для 3 фикстур (окно, дверь, два проёма рядом).

**C2. Стадия 4: панелизация (FR-8…FR-10).**
`LayoutDatum { Anchor, BondPattern, CourseSource }`, сетка = список курсов; полигональная
подрезка каждой ячейки (обёртка A2); классификация §4.4; `ResolutionPolicy` — ноль
sliver'ов на любом входе; притяжка швов к откосам в допуске из `SystemDefinition`;
SKU-квантование в корзины 5 мм.
*Приёмка:* CsCheck на случайных регионах с проёмами: сохранение площади
(панели+швы+проёмы == регион), ноль sliver'ов, отсутствие пересечений. Снапшоты перевязки
(running bond) и притяжки швов.

**C3. Стадии 5–7: узлы, крепление, BOM, ключи, provenance (FR-11…FR-14).**
Генерация откосов/отливов/перемычек с глубиной из `LayerStackup` (полная геометрия — Р6);
сущности крепления (рядовой кляммер принадлежит двум курсам); стадия 6 — сквозная передача
с заполнением полей; `BillOfMaterials` SKU × зона; `PanelKey` и стабильные ключи на каждом
элементе `LayoutResult`; `Provenance` на каждом элементе; слой валидации падает громко.
*Приёмка:* FR-13 (сходимость площадей) как инвариант; каждый элемент выхода имеет ключ и
provenance (проверяется тестом рефлексией по DTO); паспорт-генератор v1: байт-идентичный
повторный прогон.

**C4. Метаморфика, golden-набор, ворота приёмки (G1, G3).**
Метаморфические тесты: сдвиг окна ±ε → меняются только локальные ключи; масштабирование
грани → инвариант числа SKU. Golden-набор T1: ≥5 зданий (окно; дверь до низа; лента окон;
непрямоугольный контур-фронтон; плотная сетка проёмов). Прогон критериев §12 спеки.
*Приёмка:* все пороги §12, достижимые без Revit, зелёные в CI. **Ворота Р3 открыты** —
можно трогать адаптер.

### Веха D — адаптер и ассоциативность (Windows-сессии, ~8 нед)

**D1. Извлечение v2 (FR-1…FR-4) + первые фикстуры.**
`EdgeLoops` вместо `GetBoundingBox` (долг корректности №1): реальный контур + дыры,
гравитационный `FaceFrame`, объединение копланарных граней. Детекторы каталога первой
очереди: F1 (куски стены), F3 (войды), F4 (не-вертикаль), F10 (нет датума) — каждый с
`.rvt`-фикстурой (Р7). Остальные F2/F5–F9 — итеративно до конца вехи.
*Приёмка:* по каждой реализованной записи каталога — фикстура + автотест извлечения
(экспорт `GeometryInput` из фикстуры == закоммиченный golden JSON).

**D2. Diff-материализация (§8, §9.2 спеки; G2).**
`MaterializationRecord` в Extensible Storage (ключ → `UniqueId` + `OverrideFlags` +
`InputHash`); diff-apply Added/Removed/Changed/Unchanged в одном `TransactionGroup`;
no-op по хэшу; DirectShape для резаных панелей (солиды вне транзакции), FamilyInstance
для повторяемых, точечное размещение ПОК, узлы проёма полной геометрией (Р6);
shared-параметры `NVF_*`; ноль `Regenerate` в циклах; никакого face-hosting.
*Приёмка:* повторный запуск на неизменной модели — ни одного изменённого элемента;
демо G2: сдвиг окна → пересоздаются только затронутые элементы, теги нетронутых живы.

**D3. Smoke, снос v1, UI (G4).**
Windows-smoke: материализация golden-фикстуры в документ, счётчики элементов == BOM,
итоги расписаний Revit == takeoff. Снос: v1-типы Core, старые `Place*Command`, диалоги
`TaskDialog` удаляются; UI-панель читает `SystemDefinition`-документ и показывает
нарушения (≤5 групп). Обновление docs (CLAUDE.md, спека §14 — таблица миграции закрыта).
*Приёмка:* end-to-end демо на здании с проёмами; в репозитории нет ссылок на
`Substrate`/`FacadeSystem`/`TakeoffReport`; ROADMAP-шаги отмечены.

### Трек E — де-риски (параллельно, вне критпути; G6)

**E1. Кадет-Вентфасад:** демо/покупка (~₽50k), 2 недели изучения; отчёт в `docs/`:
реальная цена, охват (проёмы? BOM? развёртки?), жалобы пользователей; следствия для
бенчмарк-моции §10 гриля.
**E2. Renga-спайк:** 2 недели; извлечь грань с проёмом, разместить 200 элементов, найти
эквивалент UniqueId/Extensible Storage; отчёт. До прохождения E2 клауза №6 остаётся:
«CAD-независимость — гипотеза».
*Приёмка:* оба отчёта существуют и провязаны из гриль-документа.
